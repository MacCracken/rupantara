# rupantara Audit Report — 2026-11-09

**Scope:** a P(-1) hardening, optimization and repair sweep (first-party
standards, *P(-1): Scaffold Hardening*) over the whole repository outside
vendored `lib/`: `src/`, `programs/`, `tests/`, `dist/`, the Makefile, the CI
and release workflows, and the documents. **Baseline:** 0.5.1 (cyrius 6.7.18,
rosnet 1.2.2, tyche 1.2.2). **Result:** 0.5.2, whose outputs are bit-identical
to 0.5.1.

## Executive summary

**One HIGH defect: decoding past the context window wrote past the KV cache.**
`ru_model_fwd_row` did not check `pos`. At `pos >= T` each layer appended its K
and V rows at `pos * Ckv`:

- every layer's rows but the last V landed inside the next region of the
  cache, silently corrupting cached positions;
- the last layer's V row landed past the end of the caller's buffer, a heap
  out-of-bounds write;
- the embedding read past the learned position table.

It is reached by an ordinary mistake: generating more tokens than `T`. Probed
on the 0.5.1 code, `pos = T` returned 0 and wrote past the cache.

**Three MEDIUM defects:**

- **No config validation.** `nh = 0` or `nkv > nh` divided by zero (SIGFPE).
  `nh % nkv != 0` mapped query heads past the last K/V head, reading off the
  K/V rows. `C % nh != 0` left concat columns unwritten. `attn_bias = 2` sized
  blocks without biases, then read them, past the end of the parameters at the
  last block. Sizes could wrap an i64.
- **Unchecked token ids.** An id outside `[0, V)` read past the token
  embedding.
- **Unbounded heap growth.** Both model entries allocated their scratch on
  every call from rosnet's never-freeing bump allocator: 106.5 MB of heap per
  1,000 decode steps at GPT-2 widths.

The rest is LOW hardening (argument edge cases, CI and release integrity, test
gaps), documentation drift, and one correction to an earlier release note. The
speed work is bit-identical: attention 1.5×, embedding 9.9×, and the whole
forward 1.06× (decode 1.09×).

## Method

- **Toolchain sweeps (6.7.18), baseline then final:**
  - `cyrius test` and `cyrius test --bounds` on every suite;
  - `cyrius lint`, plus `--strict --strict-deferrals`;
  - `cyrius fmt --check`, `cyrius vet`, `cyrius deny`;
  - `cyrius doc --check`: 3 public fns undocumented, now 0;
  - `cyrius coverage --exec`: 22/22 public fns executed;
  - `cyrius audit`: it failed on docs and found no benchmarks;
  - `cyrius deps --verify` / `--locked`, `cyrius distlib --check`.
- **Manual review** of every line of `src/` (about 880 lines), the programs,
  the suites, the Makefile and both workflows.
- **Consumer check.** attn11 and anukūlana call sites were read
  (2026-11-09). Neither checks a return value. anukūlana uses 22 private layout
  helpers (`_cfg_*`, `_ru_o_*`, `_p_*`, `_b?`, `_ru_blk_base`). All are kept,
  and they are now documented as layout contract in `docs/api.md`. The 0.5.2
  source built with **cyrius 6.6.2**, both consumers' pin, passes all 164
  assertions and is bit-identical to the 0.5.1 source at 6.6.2.
- **Golden dumps.** 6,742 raw f64 bit patterns over every public forward op:
  6 model configs (MHA ±bias, GQA, MQA, 3 blocks, odd V = 37 / C = 24, C = 64)
  covering logits, probs, the cached decode and argmax, plus three leaf shapes
  with 1–3-element vector tails (LayerNorm, GELU, MLP, softmax, `linear_fwd`,
  `linear_fwd_gpu`). 0.5.1 and 0.5.2 are byte-identical on x86_64, on aarch64
  (qemu-aarch64), and at cyrius 6.6.2.
- **Mutation testing.** Eight non-equivalent mutants were all killed by the new
  suites and the fuzz harness:
  - the PV scalar tail dropped;
  - the GQA head map changed to `h % nkv`;
  - the decode position check off by one;
  - the vector add's tail dropped;
  - LN1's output aliased over the residual;
  - the `nh % nkv` check removed;
  - the token check off by one;
  - the MLP hidden aliased over the decode residual.

  Two aliasing mutants survived, and both are equivalent: `af` over `mlp_out`
  (`mlp_out` is dead when the final LN writes `af`), and the attention row
  output over its input (the Q/K/V projections consume the input first).
- **Probes:** the decode overflow on the 0.5.1 code; failing-test exit codes on
  aarch64; heap growth over a 1,000-step decode. Every suite was also run under
  `cyrius test --bounds` and under qemu-aarch64 (`--aarch64`).
- **Benchmarks:** `scripts/bench-history.sh` (new), before and after, one
  session, median of 3 runs, 10 rows plus 2 new.

## Observations — not changed, and why

- **The scores and LM-head dots keep their 4-lane `f64v_fmadd` chains.** That
  lane order is the bit contract. Packing two keys or two vocabulary rows into
  one call needs a gather copy that costs what it saves. The scores are now
  most of the attention cost, and the head is about 30% of a GPT-2-small decode
  step's multiply-adds (V·C against 12 layers of 12C²).
- **GELU stays at about 96 ns per element**, nearly all of it `f64_tanh`. A
  faster tanh changes bits.
- **No AVX2.** It would need a runtime CPU check and a new stdlib leaf in the
  bundle, and it changes nothing about rounding.
- **The allocating entries still allocate.** Changing their memory behaviour
  needs either a module-global cache (which would make them non-reentrant, a
  silent change) or a new signature. They are documented instead, and `_s` is
  the fix.
- **anukūlana's decode loop** (`src/main.cyr`) calls `ru_model_fwd_row` per
  token, so it carries finding 4 until it moves to `ru_model_fwd_row_s`. That
  is a cross-repo change, left to the maintainer.
- **`ru_model_fwd` always runs T tokens.** A shorter prompt is padded; this is
  documented and exact because attention is causal. A variable-length entry
  would be a feature, not a repair.
- **`linear_fwd_gpu` is not reentrant** (module-global tile scratch). This is
  documented. Its only caller is the AGNOS crown proof.
- **The CI installer comes from cyrius `main`**, not a pinned ref. That is the
  ecosystem-wide pattern (rosnet and the other repos do the same). Pinning it
  is a cross-repo decision.
- **x86_64 and aarch64 differ** where cyrius fuses the packed multiply-add
  (4,749 of the 6,742 dump values). This is pre-existing and documented.
- **`linear_fwd_gpu`'s CPU fallback is not bit-identical to `linear_fwd` on
  aarch64** for a ragged last tile. Running every suite under qemu-aarch64, a
  first for this repo, found this; 0.5.1 fails the same case. The fallback
  computes each tile on zero-padded 8×8 blocks, so a ragged tile's last `N % 4`
  columns take `linear_fwd`'s packed body (FMLA, fused on aarch64) where the
  full problem takes the unfused scalar tail. On x86_64, the only GPU target,
  both round alike, and the function's comment already scoped its claim to
  x86. Fixing the fallback to exact-shape tiles would stop CI from checking the
  crown's padded gather/scatter off-hardware. So the caveat is documented
  (`src/gpu.cyr`, `docs/api.md`) and `tests/tcyr/gpu.tcyr` holds those columns
  to 1e-12 on aarch64 and everything else bit-exact.

## Downstream

No public signature changed, and every output is bit-identical to 0.5.1 for
valid input, on x86_64 and aarch64 and at cyrius 6.6.2 and 6.7.18. Invalid
input that used to run into undefined behaviour now returns a negative code.
attn11 and anukūlana pass valid configs and ignore the return values, so they
see no change. New public functions: `ru_cfg_check`, `ru_model_fwd_s`,
`ru_model_fwd_row_s`, `ru_model_scratch_count`, `ru_decode_scratch_count`, and
the `RU_*` codes. The bundle's sidecar is unchanged (`math`, `ganita`), and it
compiles under cyrius 6.6.2. Consumers' suites were not re-run.
